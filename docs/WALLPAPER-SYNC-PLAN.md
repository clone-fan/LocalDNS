# 壁纸多端存储方案

状态：用户于 2026-10-18 取消独立壁纸同步服务方案，随后要求移除浏览器本地图库管理。当前 UI 2026.10.18.11 仅提供单张壁纸设置；旧图库当前使用的壁纸继续保留。独立服务已停用并取消自启，资源数据保留。未上线的 .10 原型已归档到本机忽略目录，不参与后续打包。

下方为已取消的设计提案，仅作历史记录。当前行为见 [.11 说明](releases/fjgac-ui-v2026.10.18.11.md)。

## 建议

服务器保存共享壁纸库和全局默认选择；浏览器负责缓存，并允许本设备单独设置。手机、平板和电脑访问同一台 LocalDNS 时，共享同一份资源。

| 保存范围 | 使用方式 |
| --- | --- |
| 所有设备（推荐） | 保存到服务器，其他设备打开页面或回到前台时读取共享设置 |
| 仅本设备 | 保留现有 IndexedDB 方式，覆盖服务器默认选择，不影响其他设备 |

图片与壁纸 URL 是壁纸资源；暗化、适配方式可随共享壁纸保存。导航布局、系统明暗偏好和设备阅读字号继续独立，避免手机与桌面互相改动。

## 外观面板

1. “壁纸”标题旁显示保存范围，提供“所有设备 / 仅本设备”选择。
2. “上传图片…”上传到共享库；上传完成后确认应用范围。
3. “管理壁纸”打开缩略图列表，显示名称、文件大小和“当前共享壁纸”标记，支持预览、应用、重命名及删除。
4. “恢复默认”只取消当前范围的自定义选择；服务器图片继续留在资源库中。
5. 保存提示明确写“已保存到服务器 · 所有设备共用”或“已保存到当前浏览器”。不把本地保存提示写成已同步。

## 删除

- 普通资源：点击“删除”，显示图片预览和文件名，确认后删除服务器图片及其记录。
- 当前共享壁纸：提示“删除后，共享壁纸将恢复默认；各设备下次同步时更新”，确认按钮为“恢复默认并删除”。先更新默认选择，再删除文件。
- 本设备覆盖：设备引用已删除资源时，下次读取或图片加载失败后回退到共享默认背景，并给出一次说明。没有设备在线清单时，不展示“有几台设备正在使用”等无法确认的数据。
- 图片删除失败时保留资源记录，明确显示失败原因并允许重试；恢复默认成功但文件删除失败时分别提示结果。
- 已经缓存在离线设备上的图片，在该设备重新连网前可能继续显示，不承诺立即清除所有设备缓存。

## 服务端存放与接口需求

建议图片放在独立的持久化资源目录，元数据放在配置目录。UI 更新和 DNS 内核更新不覆盖它们；备份时包含两者。

后端需提供壁纸列表、上传、读取图片、改名、删除，以及共享选择的读取和保存接口。图片使用生成的资源 ID，原文件名只作展示；写入完成后才更新元数据，并提供版本号以检查多端同时修改。

目前此仓库只有 UI 源码，已接入的后端接口中没有壁纸资源上传/删除能力。服务器模式需由 LocalDNS 后端提供对应能力；前端不应把浏览器保存伪装为服务器保存。

## 旧图片迁移

现有本地壁纸继续保留。用户主动选择“上传当前壁纸并设为共享”后再上传；成功后切换共享模式。上传失败时继续使用原来的本地图片。

## 实施顺序

1. 确定并实现后端持久化、版本检查和资源增删接口。
2. 接入共享壁纸库、删除流程及保存范围选择。
3. 验证两台设备读取、覆盖、恢复默认、删除正在使用的图片和离线回退。
